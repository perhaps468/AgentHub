# Left Sidebar Menu Skill

## 使用场景

当用户要求在 AgentHub 前端实现或维护以下能力时使用本 Skill：

- 左侧菜单栏或侧边导航。
- 头像按钮，点击后展示用户信息弹框。
- 用户弹框中展示名字、编辑资料入口和退出按钮。
- 编辑资料入口，点击后展示可关闭、可确认的资料编辑弹窗。
- 消息列表入口或消息菜单项。
- Agent 列表入口。
- 消息列表和 Agent 列表互斥展示，点击消息列表时只展示消息列表，点击 Agent 列表时只展示 Agent 列表。
- Agent 列表中每个 Agent 展示头像、名字、能力标签。

## 项目上下文

当前项目是 Vue 3 + TypeScript + Pinia + Element Plus 前端。优先查看并复用这些文件和现有风格：

- `src/components/zhu.vue`：主布局、左侧区域、聊天目标和会话列表相关逻辑。
- `src/types/agenthub.ts`：AgentHub 相关类型定义。
- `src/veiws/Chat-show-area.vue`：聊天展示区域。
- `src/veiws/Chat-input-area.vue`：聊天输入区域。

如已有菜单、会话或 Agent 数据结构，优先小步扩展，不重写整体布局。

## 实现目标

1. 左侧菜单栏包含三个核心入口：
   - 头像按钮。
   - 消息列表按钮。
   - Agent 列表按钮。
2. 头像按钮点击后展示弹框或下拉框，内容包括：
   - 用户头像。
   - 用户名字。
   - 编辑资料按钮。
   - 退出按钮。
3. 点击编辑资料按钮后展示资料编辑弹窗，弹窗支持关闭和确认。
4. 消息列表按钮用于切换到消息/会话列表，并且只展示消息/会话列表。
5. Agent 列表按钮用于切换到 Agent 列表，并且只展示 Agent 列表。
6. 消息列表面板与 Agent 列表面板互斥展示，不要同时渲染在同一内容区域。
7. Agent 列表中的每个 Agent 应展示：
   - Agent 头像。
   - Agent 名字。
   - Agent 能力标签。
8. UI 延续项目现有简洁风格，优先使用白色、浅灰、深灰和现有主题色。
9. 后端契约未确认时，使用前端 mock 数据或兼容字段，不阻塞 UI 验证。

## 不允许破坏的现有功能

- 不删除现有聊天组件。
- 不移除群聊、私聊、单 Agent 会话等已有入口。
- 不改变 `targetId === '1'` 表示群聊的现有判断。
- 不删除已有会话列表功能。
- 不修改现有接口语义，除非后端契约已确认。
- 不删除文件；确实需要删除时必须先向用户确认。

## 推荐数据模型

后端未确认前，可在前端使用兼容 mock 模型：

```ts
interface SidebarUser {
  id: string
  name: string
  avatar: string
  email?: string
  bio?: string
}

interface SidebarAgent {
  id: string
  name: string
  avatar: string
  capabilityTags: string[]
  description?: string
}

type SidebarPanel = 'messages' | 'agents'
```

约定：

- `SidebarPanel` 控制当前展示消息列表还是 Agent 列表，同一时刻只能有一个面板处于可见状态。
- 点击消息列表按钮时设置 `activeSidebarPanel = 'messages'`，内容区只渲染消息/会话列表。
- 点击 Agent 列表按钮时设置 `activeSidebarPanel = 'agents'`，内容区只渲染 Agent 列表。
- `capabilityTags` 最多优先展示 3 到 4 个，超出时用省略或 `+N` 表示。
- 头像为空时提供默认占位头像或首字母占位。
- 编辑资料字段优先兼容现有用户字段；后端未确认时可只支持名称、头像、邮箱、简介等前端 mock 字段。

## 推荐改动路径

优先小步扩展，而不是重写：

1. 先阅读 `src/components/zhu.vue`，确认当前左侧布局结构。
2. 如项目已有用户、会话、Agent 类型，优先复用；缺失时再补充最小类型。
3. 在左侧菜单区域增加 `activeSidebarPanel` 状态，默认展示消息列表。
4. 新增头像按钮、用户弹框状态和编辑资料弹窗状态，例如 `showUserPopover`、`showEditProfileDialog`。
5. 为消息列表按钮和 Agent 列表按钮增加激活态，并确保两个面板互斥展示。
6. 将原消息/会话列表放入消息面板，不改变原有逻辑。
7. 新增 Agent 列表面板，使用 mock 或现有 Agent 数据渲染头像、名字、能力标签。
8. 在用户弹框中新增编辑资料按钮，点击后关闭或保留用户弹框，并打开编辑资料弹窗。
9. 编辑资料弹窗应支持关闭和确认；确认时优先调用已有用户资料更新逻辑，未接后端时先更新本地状态。
10. 退出按钮先接入已有退出逻辑；如果不存在，用明确的 `handleLogout` 占位，并避免破坏路由和登录态。

## 交互规范

### 头像按钮

- 点击头像切换用户弹框显示状态。
- 弹框展示用户头像、用户名字、编辑资料按钮和退出按钮。
- 点击编辑资料按钮时打开编辑资料弹窗。
- 编辑资料弹窗支持关闭和确认；关闭不保存更改，确认保存更改。
- 点击退出按钮时，优先调用已有退出逻辑。
- 如果没有退出接口，保留 TODO 级别的函数命名即可，不要伪造后端请求。

### 消息列表按钮

- 点击后设置当前面板为 `messages`。
- 内容区域只展示消息/会话列表，不展示 Agent 列表。
- 保留现有消息列表、搜索、置顶、归档、最近活跃排序等能力。
- 激活态应清晰可见。

### Agent 列表按钮

- 点击后设置当前面板为 `agents`。
- 内容区域只展示 Agent 列表，不展示消息/会话列表。
- 每个 Agent 项支持点击选择；若已有单 Agent 会话逻辑，应复用现有选择或新建会话流程。
- Agent 能力标签使用紧凑样式，避免挤压名称。

## 编辑资料弹窗规范

编辑资料弹窗建议满足：

- 从当前用户信息初始化表单，避免打开空白表单。
- 至少支持编辑名字；如已有字段可支持头像、邮箱、简介等。
- 提供关闭/取消按钮，点击后关闭弹窗且不保存本次输入。
- 提供确认按钮，点击后校验并保存资料。
- 保存成功后同步更新头像弹框中的用户信息。
- 未接入后端时，只更新前端本地 mock 状态，不阻塞 UI 验证。

## Agent 列表渲染规范

每个 Agent 项建议包含：

- 左侧圆形头像。
- 中间名称和可选描述。
- 下方或右侧能力标签。
- hover 态和 selected 态。

能力标签建议：

- 使用浅色背景和深灰文字。
- 文案短小，例如 `代码生成`、`需求分析`、`测试`、`文档`。
- 超出一行时允许换行或截断，但不要撑破侧栏。

## 样式规范

- 优先使用现有 CSS 变量、类名和布局尺寸。
- 菜单按钮保持视觉一致：图标/头像居中、hover 态、active 态。
- 左侧菜单栏宽度固定，内容面板宽度与现有侧栏一致。
- 弹框层级要高于侧栏内容，但不要遮挡主聊天区域过多。
- 移动端或窄屏下，优先保持按钮可点击和列表可滚动。

## 中文注释规范

- 文档和用户说明使用中文。
- 代码注释仅解释非显而易见的业务约束。
- 不写“定义变量”“调用函数”“返回结果”这类无意义注释。

## 验收清单

- 左侧菜单栏能看到头像、消息列表、Agent 列表三个按钮。
- 点击头像能展示用户名字、编辑资料按钮和退出按钮。
- 点击编辑资料按钮能打开资料编辑弹窗。
- 编辑资料弹窗可以关闭，关闭不保存更改。
- 编辑资料弹窗可以确认，确认后保存并更新用户信息展示。
- 点击消息列表按钮时，只显示原消息/会话列表。
- 点击 Agent 列表按钮时，只显示 Agent 列表。
- 每个 Agent 都展示头像、名字和能力标签。
- Agent 列表样式不会撑破左侧栏，长标签有合理处理。
- 原有群聊、私聊、单 Agent 会话和聊天输入展示不受影响。
- 未删除任何文件。
