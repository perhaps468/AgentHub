## 一、已确认的技术决策

| # | 决策项 | 确认方案 | 决策原因 |
|---|--------|----------|----------|
| 1 | AI Provider | **Claude Only（MVP）** | 最快落地，adapter 模式预留扩展位，后续可快速接入 OpenAI |
| 2 | Web 预览 | **iframe + 后端静态文件服务** | MVP 阶段足够简单，后续按需升级 WebContainers |
| 3 | 用户体系 | **写死 `dev_user`** | 教学/MVP 场景，身份验证非重点，通过 `.env` 统一管理 |
| 4 | VFS 持久化 | **Redis 存完整 VFS 内容**，`Accept` 后写 `/tmp/agent-projects/{project_id}/` | 简化落盘逻辑，后端提供 `/api/preview/{project_id}/<path>` 路由代理给 iframe |
| 5 | WebSocket 流式策略 | **按句子 chunk 发送**（非逐 token），每个消息带 `stream_id` 追踪 | 平衡性能与前端渲染体验 |
| 6 | 多 Agent 协作触发 | **MVP 单聊 + 固定四角色流水线**，群聊模式作为 P2 | 降低初期复杂度 |
| 7 | 前端路由设计 | `/` → `/chat` → `/chat/:sessionId` → `/project` → `/agents` | 标准 SPA 路由结构 |
| 8 | Diff 展示 | **MVP diff2html（展示型）**，P2 升级 Monaco Diff Editor | 先跑通核心流程 |
| 9 | 部署策略 | **开发期本地运行**，Docker 只用于 PostgreSQL + Redis | 减少 CI/CD 干扰开发节奏 |

## 四、WebSocket 消息协议（最终版）

### 4.1 服务端 → 客户端

```typescript
// shared/index.ts 中定义的所有类型

type MessageType =
  | 'chat_stream'    // 流式文字输出
  | 'task_update'   // 任务列表更新
  | 'code_diff'     // 代码 Diff 卡片
  | 'system_status' // 系统状态通知
  | 'vfs_update'    // VFS 文件变更
  | 'agent_typing'  // Agent 正在输入
  | 'error';        // 错误消息

interface BaseMessage {
  type: MessageType;
  agent_role: 'Human' | 'PM' | 'Planner' | 'Coder' | 'Reviewer' | 'System';
  timestamp: string;
  stream_id: string; // 用于追踪同一消息的多个 chunk
}

interface ChatStreamMessage extends BaseMessage {
  type: 'chat_stream';
  message_id: string;
  content_chunk: string;  // 按句子 chunk，非逐 token
  is_final: boolean;     // 最后一条 chunk 时为 true
}

interface TaskItem {
  id: string;
  title: string;
  status: 'pending' | 'doing' | 'done' | 'rejected';
  assignee: string;
  priority: number;
}

interface CodeDiffMessage extends BaseMessage {
  type: 'code_diff';
  diff_id: string;
  file_path: string;
  old_content: string;
  new_content: string;
  diff_summary: string;
  status: 'pending' | 'accepted' | 'rejected';
}
```

### 4.2 客户端 → 服务端

```typescript
type ClientAction = 'send_message' | 'accept_code' | 'reject_code' | 'deploy';

interface SendMessage {
  action: 'send_message';
  session_id: string;
  content: string;
  mentioned_agents?: string[];  // @ 提及的 Agent 角色
}

interface AcceptCode {
  action: 'accept_code';
  diff_id: string;
}
```

## 五、数据库设计

### 5.1 表结构

```sql
-- users 表（简化版，MVP 只预置 dev_user）
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    username VARCHAR(50) UNIQUE NOT NULL,
    created_at TIMESTAMP DEFAULT NOW()
);

-- agents 表
CREATE TABLE agents (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name VARCHAR(100) NOT NULL,
    role VARCHAR(50) NOT NULL,  -- PM, Planner, Coder, Reviewer
    provider VARCHAR(50) NOT NULL,  -- claude, openai, ollama
    model VARCHAR(100),
    system_prompt TEXT,
    avatar_url VARCHAR(500),
    capabilities JSONB DEFAULT '[]',
    created_by UUID REFERENCES users(id),
    created_at TIMESTAMP DEFAULT NOW()
);

-- projects 表
CREATE TABLE projects (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    owner_id UUID REFERENCES users(id),
    name VARCHAR(200) NOT NULL,
    description TEXT,
    vfs_state JSONB DEFAULT '{}',
    status VARCHAR(20) DEFAULT 'active',
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);

-- chat_sessions 表
CREATE TABLE chat_sessions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    project_id UUID REFERENCES projects(id) ON DELETE CASCADE,
    owner_id UUID REFERENCES users(id),
    title VARCHAR(200),
    mode VARCHAR(20) DEFAULT 'single',  -- single | group（P2）
    is_pinned BOOLEAN DEFAULT FALSE,
    is_archived BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);

-- session_participants（群聊成员，P2 实现）
CREATE TABLE session_participants (
    session_id UUID REFERENCES chat_sessions(id) ON DELETE CASCADE,
    agent_id UUID REFERENCES agents(id) ON DELETE CASCADE,
    joined_at TIMESTAMP DEFAULT NOW(),
    PRIMARY KEY (session_id, agent_id)
);

-- messages 表
CREATE TABLE messages (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    session_id UUID REFERENCES chat_sessions(id) ON DELETE CASCADE,
    sender_type VARCHAR(20) NOT NULL,  -- human | agent | system
    sender_id UUID,
    sender_role VARCHAR(50),  -- Human, PM, Planner, Coder, Reviewer
    content TEXT NOT NULL,
    content_type VARCHAR(20) DEFAULT 'text',
    metadata JSONB DEFAULT '{}',
    is_pinned BOOLEAN DEFAULT FALSE,
    parent_message_id UUID REFERENCES messages(id),
    created_at TIMESTAMP DEFAULT NOW()
);

-- tasks 表
CREATE TABLE tasks (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    project_id UUID REFERENCES projects(id) ON DELETE CASCADE,
    session_id UUID REFERENCES chat_sessions(id),
    parent_task_id UUID REFERENCES tasks(id),
    title VARCHAR(500) NOT NULL,
    description TEXT,
    status VARCHAR(20) DEFAULT 'pending',
    assignee VARCHAR(50),
    priority INTEGER DEFAULT 0,
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);

-- code_diffs 表
CREATE TABLE code_diffs (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    message_id UUID REFERENCES messages(id) ON DELETE CASCADE,
    project_id UUID REFERENCES projects(id) ON DELETE CASCADE,
    file_path VARCHAR(500) NOT NULL,
    old_content TEXT,
    new_content TEXT NOT NULL,
    diff_summary TEXT,
    status VARCHAR(20) DEFAULT 'pending',
    created_at TIMESTAMP DEFAULT NOW()
);
```

## 七、VFS 详细设计

### 7.1 数据结构

Redis 中以 `files:{project_id}` 为 key，存储：

```json
{
  "project_id": "proj_123",
  "files": {
    "/src/index.html": {
      "content": "<html>...</html>",
      "version": 1,
      "updated_at": "2026-05-20T10:00:00Z"
    },
    "/src/style.css": {
      "content": "body { ... }",
      "version": 1,
      "updated_at": "2026-05-20T10:00:00Z"
    }
  }
}
```

### 7.2 Accept Code 流程

```
用户点击 "Accept"
  → 前端发送 { "action": "accept_code", "diff_id": "xxx" }
  → 后端 VFSService.accept_diff(diff_id)
      → 从 Redis 读取 VFS
      → 将 diff 应用于对应文件（old_content → new_content）
      → version++
      → 写回 Redis
      → 落盘到 /tmp/agent-projects/{project_id}/{file_path}
      → 更新 code_diffs 表 status = 'accepted'
      → 推送 vfs_update 消息给前端
  → 前端刷新文件树
```

### 7.3 Reject Code 流程

```
用户点击 "Reject"
  → 前端发送 { "action": "reject_code", "diff_id": "xxx" }
  → 后端更新 code_diffs status = 'rejected'
  → 唤醒 Coder Node 重新生成（携带拒绝原因）
  → 推送新 diff 消息
```

## 八、Agent 协作 SOP（最终版）

### 8.1 全局状态

```python
class AgentState(TypedDict):
    project_id: str
    project_context: str          # PM 总结的项目全局描述
    prd_content: str             # PM 输出的 Markdown PRD
    task_dag: list[dict]         # Planner 输出的任务 DAG
    vfs_snapshot: dict            # 当前 VFS 目录树
    messages: list[dict]         # 对话历史
    pending_diffs: list[dict]    # 待接受的 Diff
    current_phase: str            # "requirement" | "planning" | "coding" | "review" | "done"
    active_agents: list[str]     # 当前活跃的 Agent 角色
```

### 8.2 节点定义

| 节点 | System Prompt 要点 | 触发条件 | 输出终点 |
|------|-------------------|----------|----------|
| **PM** | 追问细节 → 输出 Markdown PRD（核心功能、页面结构、技术约束） | 用户发需求 | 唤醒 Planner |
| **Planner** | 读 PRD → 结合 vfs_snapshot → 输出 JSON 任务 DAG（id/title/status/assignee/priority） | PM 输出 PRD | 唤醒 Coder（按 priority 依次） |
| **Coder** | 认领任务 → 只输出针对特定文件的 Diff，不写解释 | 任务队列有待处理 | 唤醒 Reviewer |
| **Reviewer** | 审查 Diff → `[APPROVE]` → 等待用户验收；`[REJECT]` + 原因 → 打回 Coder | Coder 提交新代码 | 等待用户 Accept，或打回 Coder |

### 8.3 流转图

```
用户需求
  ↓
[PM Node] 需求澄清 → 输出 Markdown PRD
  ↓
[Planner Node] 任务拆解 → 输出 JSON DAG
  ↓
[Coder Node] 认领任务 → 输出 Code Diff（不落盘）
  ↓
[Reviewer Node] 审查
  ├─ [APPROVE] → 推送 Diff 卡片给用户 → 等待 Accept
  └─ [REJECT] → 打回 Coder → 重新生成
  ↓
用户点击 Accept
  ↓
[VFSService] 更新 Redis VFS → 落盘 /tmp/
  ↓
预览卡片出现（如果生成的是 HTML）
```
