# P1-1 聊天 UI、会话列表与多会话切换

## 任务目标

围绕 Phase1 的聊天入口能力，落地可直接使用的 IM 聊天壳层，支持创建会话、展示会话列表、切换当前会话，并在刷新后恢复最近会话状态。

## 当前范围

- 前端聊天主界面骨架：会话列表区、聊天展示区、输入区、会话头部信息区
- 会话创建、会话列表查询、会话详情查询三类基础接口
- 前端 `session store` 的统一状态管理与页面刷新恢复
- 单聊/群聊标签、置顶状态、最近活跃时间等会话摘要信息展示

## 不做什么

- 不实现实时消息推送与消息历史恢复，这部分属于 `P1-2`
- 不实现流式输出、Runtime、工具调用、工作区执行链路
- 不扩展复杂筛选、搜索、归档管理、拖拽排序等增强交互
- 不引入完整权限系统，只要求沿用当前最小用户身份边界

## 依赖与前置条件

- 需要已有最小登录态或开发态固定用户身份注入能力
- 需要后端已有 `Session` 基础模型或可新增对应持久化结构
- 需要前端已有基础路由、页面容器和 API 调用能力
- `workspace_id` 可先允许为空或引用已有工作区记录，但字段需要在接口中保留

## 涉及模块

### 后端

- 会话模型与持久化：`Session`
- 会话接口层：`POST /api/sessions`、`GET /api/sessions`、`GET /api/sessions/{session_id}`
- 会话查询排序与当前用户过滤逻辑

### 前端

- 聊天主页面布局与会话列表组件
- 会话创建入口与当前会话切换行为
- `session store`：列表、当前激活会话、详情缓存、本地恢复、回源刷新

## 数据模型要求

`Session` 至少包含以下字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | string | 是 | 会话唯一标识 |
| `title` | string | 是 | 会话标题 |
| `mode` | enum | 是 | 会话模式，至少支持 `single`、`group` |
| `owner_id` | string | 是 | 当前会话归属用户 |
| `workspace_id` | string \| null | 否 | 绑定工作区 |
| `is_pinned` | boolean | 是 | 是否置顶 |
| `is_archived` | boolean | 是 | 是否归档 |
| `created_at` | datetime | 是 | 创建时间 |
| `updated_at` | datetime | 是 | 最后更新时间 |

## 接口契约

### 1. 创建会话

- 方法：`POST /api/sessions`
- 认证：必需，使用当前登录用户身份

请求体：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `title` | string | 是 | 会话标题，允许前端传默认标题 |
| `mode` | enum | 是 | `single` 或 `group` |
| `workspace_id` | string \| null | 否 | 绑定工作区 ID |

成功响应：`201 Created`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 新会话 ID |
| `title` | string | 会话标题 |
| `mode` | enum | 会话模式 |
| `owner_id` | string | 当前用户 ID |
| `workspace_id` | string \| null | 绑定工作区 |
| `is_pinned` | boolean | 是否置顶 |
| `is_archived` | boolean | 是否归档 |
| `created_at` | datetime | 创建时间 |
| `updated_at` | datetime | 更新时间 |

主要错误：

- `400 Bad Request`：`title` 或 `mode` 非法
- `401 Unauthorized`：未登录
- `404 Not Found`：`workspace_id` 不存在
- `403 Forbidden`：`workspace_id` 不属于当前用户

### 2. 查询会话列表

- 方法：`GET /api/sessions`
- 认证：必需

查询参数：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `include_archived` | boolean | 否 | 默认 `false` |

成功响应：`200 OK`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `items` | Session[] | 当前用户可见会话列表 |
| `total` | number | 会话总数 |

排序规则：

- `is_pinned desc`
- `updated_at desc`

主要错误：

- `401 Unauthorized`：未登录

### 3. 查询会话详情

- 方法：`GET /api/sessions/{session_id}`
- 认证：必需

路径参数：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `session_id` | string | 是 | 会话 ID |

成功响应：`200 OK`

返回字段与 `Session` 基础字段保持一致，至少包含：

- `id`
- `title`
- `mode`
- `owner_id`
- `workspace_id`
- `is_pinned`
- `is_archived`
- `created_at`
- `updated_at`

主要错误：

- `401 Unauthorized`：未登录
- `403 Forbidden`：无权访问该会话
- `404 Not Found`：会话不存在

## 详细实现步骤

1. 梳理当前前后端已有会话能力，确认 `Session` 模型字段缺口和现有路由可复用部分。
2. 在后端补齐 `Session` 基础字段与最小持久化读写逻辑，确保能按用户隔离查询。
3. 实现 `POST /api/sessions`，完成参数校验、用户注入、可选工作区校验与创建返回。
4. 实现 `GET /api/sessions`，支持 `include_archived` 参数，并按 `is_pinned desc, updated_at desc` 稳定排序。
5. 实现 `GET /api/sessions/{session_id}`，统一走当前用户权限校验与详情查询。
6. 在前端搭建聊天页面骨架，完成会话列表、会话头部、空态和加载态展示。
7. 建立 `session store`，统一管理列表、当前会话 ID、会话详情缓存、本地持久化键和回源刷新逻辑。
8. 接入会话创建与切换流程：创建成功后插入列表、切换时拉取详情并刷新当前上下文。
9. 完成页面刷新恢复：优先恢复本地最近会话 ID 和缓存，再回源更新，处理会话已删除或无权限场景。
10. 联调验证多会话创建、切换、刷新恢复和排序一致性。

## 测试方案

### 后端测试

- 会话创建成功：合法 `title`、`mode`、`workspace_id`
- 会话创建失败：缺失必填字段、非法 `mode`、越权 `workspace_id`
- 会话列表只返回当前用户数据
- 会话列表按置顶和更新时间排序正确
- 会话详情对无权限用户返回 `403` 或等价错误

### 前端测试

- 首次进入页面能拉取并展示会话列表
- 创建会话后列表即时更新并自动切换到新会话
- 点击不同会话可稳定切换头部与聊天区域上下文
- 刷新页面后能恢复最近一次激活会话
- 本地缓存失效或目标会话不存在时能优雅回退到默认态

### 联调验证

- 多会话创建后刷新页面，列表顺序与激活状态保持一致
- 单聊和群聊会话在列表中都能正确显示模式标签

## 验收标准

- 用户可以创建、查看并切换多个会话
- 前端聊天页面具备稳定的基础布局与会话入口，不再依赖临时 mock 数据
- 刷新页面后，最近会话列表和当前激活会话可以恢复
- 后端接口对当前用户会话边界、排序和详情查询表现一致
- 本 task 不引入超出 Phase1 范围的实时消息或 Runtime 逻辑
